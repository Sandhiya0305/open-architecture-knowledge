# Learning path

A short route through the material. Read in order if you are new to software architecture; jump to a topic when it matches a problem you are working on.

## 1. Build the vocabulary

- [Architecture and frameworks](../fundamentals/architecture-vs-framework.md)
- [Quality attributes](../fundamentals/quality-attributes.md)
- [Architecture decision process](../fundamentals/decision-process.md)

## 2. Understand application structure

- [Layered architecture](../architectures/layered.md)
- [Modular monolith](../architectures/modular-monolith.md)
- [Microservices](../architectures/microservices.md)
- [Clean Architecture](../architectures/clean-architecture.md)

## 3. Understand communication and change

- [Event-driven architecture](../architectures/event-driven.md)
- [Choosing an architecture](../comparisons/choosing-an-architecture.md)

## 4. Connect patterns to implementation

Browse the [frameworks and libraries catalogue](../technologies/index.md) after identifying the responsibilities your application needs. A framework is an implementation choice; it does not automatically enforce an architecture.

## A useful habit

For each pattern, write down the problem it addresses, the boundaries it introduces, the operational costs it adds and the evidence you would need to validate its fit. There is no requirement to adopt every pattern in this path.
