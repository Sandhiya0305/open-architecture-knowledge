## How entries are selected

- The tool has a distinct role in application development, delivery or operation.
- Official documentation or a maintained project source is available.
- The entry adds useful coverage beyond another tool already listed for the same role.
- The entry is presented as an example, not as a popularity ranking or endorsement.

The catalogue does not infer quality or performance from stars, downloads or mentions. Check the license and supported versions for the exact release you plan to use; licensing can change between major versions.

## Keeping the catalogue current

Run a short monthly scan for major releases, support changes and licensing notices. Complete a full review of the catalogue quarterly, checking official documentation and project maintenance information. Remove tools that are archived, unsupported or no longer relevant. The [catalogue review log](review-log.md) records the date, scope and changes in one place.

## Licensing and maintenance checks

A release cadence is not a universal measure of project health, so this catalogue does not assign an unverified active label to every tool. The review log records the scope of manual checks. Before adopting a tool, inspect the official release history, support policy and license for the exact version you intend to deploy. Version-specific licensing notes are included where the project has changed its licensing model.
